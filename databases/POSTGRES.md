# PostgreSQL Code Standards

## 1. Data Modeling

`[PG-001]` **MUST**: PostgreSQL tables must exist under a dedicated schema. This ensures that entities and resources can be logically grouped, segregated, and managed. The default schema should be called `base`.

`[PG-002]` **MUST**: PostgreSQL table names and column names must be in snake_case.

`[PG-003]` **MUST**: PostgreSQL table names must be the singular noun of the entity they model. For example, a table storing users must be named user (e.g. `base.user`, where base is the schema).

`[PG-004]` **MUST**: Where a column references a row in another table, it must declare a foreign key constraint against that table to enforce referential integrity.

`[PG-005]` **MUST**: Link (junction) tables must be used to model many-to-many relationships, and where several tables reference a shared, generic resource. For example, rather than adding user- or job-specific foreign keys to base.document, both `base.user` and `base.job` link to it through their own link tables. See `examples/POSTGRES/link-tables.md` for a full schema example.

## 2. Required Columns and Types

`[PG-006]` **MUST**: Datetime entries must be stored in either UTC ISO8601 format or as unix timestamps.

`[PG-007]` **MUST**: All tables must have a `created_at` and `updated_at` timestamp column, providing the timestamp of row creation and updated respectively. Timestamps must be in UTC ISO8601 format.

`[PG-008]` **MUST**: The `created_at` and `updated_at` timestamp column must have the current UTC timestamp configured as a server default. A trigger must be created for the `updated_at` column that automatically updates the value of `updated_at` to the current UTC timestamp when a row is updated. See `examples/POSTGRES/timestamp-columns.md` for an example trigger function and its `alembic` migration.

`[PG-009]` **MUST**: Postgres persistence layers must implement transactions when executing multiple updates. This facilitates atomic operations, and ensures data consistency by preventing partial updates.

`[PG-010]` **MUST**: Postgres schemas must be created and configured using `alembic`. `sqlalchemy` must be used where possible to define columns, types, functions, and other schema entities.

`[PG-011]` **SHOULD**: ID fields should consist of high-entropy values, such as UUIDs. Avoid using incrementing integers as IDs. Use UUIDs with hyphens removed for ID columns unless otherwise instructed. Ensure that a secure algorithm such as uuid4 or uuid7 is used to reduce the risk of UUID enumeration.

`[PG-012]` **SHOULD**: Primary ID columns should be internal, and generated by the application itself. If entities modeled in a database refer to external resources, create a link table to map internal IDs to external IDs. For example, when using `Auth0`, user entities should not be keyed on the `Auth0` user ID. Rather, an internal ID should be generated, and a link that that maps the internal ID to the Auth0 ID should be created.

`[PG-013]` **SHOULD**: Avoid using complex data types such arrays and JSONB types in postgres tables.
