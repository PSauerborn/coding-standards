# Work Plan: Manually-Triggered Release Workflows (Indexer + Standards Tree)

Work Plan ID: WP-002
Created Date: 2026-08-02
Type: feature
Spec: docs/specs/SPEC-002.md
Scale: Medium
Description: Add two manually-triggered GitHub Actions workflows that (a) cross-build and release the Go indexer binaries into `bin/` and (b) regenerate and release `standards-tree.yaml`, each gated on a validated, unused semver and each tagging `main` on success.
Estimated Impact: 4 files

## Objective

Automate the two release paths that are currently manual: building/committing the indexer binaries and regenerating/committing `standards-tree.yaml`. Each release is operator-triggered with a semver input, hard-gated on semver validity and tag non-existence, and finishes by tagging `main` (`v{semver}-indexer` / `v{semver}-standards`).

## Background

The repository has no CI pipelines. The indexer is built by hand and `standards-tree.yaml` is regenerated and hand-merged locally. SPEC-002 introduces `release-indexer.yaml` and `release-standards.yaml` under `.github/workflows/` (the `.github` directory does not yet exist on `feature/ci`). Because the indexer walk skips dot-prefixed directories, the new workflow files cannot join the standards tree, and no `indexer/integration_test.go` snapshot changes are needed.

Decision-precedence rulings from the user (these override any contrary reading of the spec):

1. Both pipelines commit as `github-actions[bot]` per spec §6.3. The `ci-bot` name in REQ-3.2 is a spec error and is superseded.
2. The target branch is `main` (default branch was renamed from `master`). Implement against `main` exactly as the spec states.
3. The root `Makefile` `index` target is OUT OF SCOPE and must not be modified, even though `./bin/indexer` will no longer resolve after a release.
4. WAIVED (do not implement): skip-if-unchanged for the indexer binary commit (only `standards-tree.yaml` gets skip-if-unchanged per spec §7 / AC-7); a diagnostic for a missing `bin/indexer-linux-amd64` on first standards release; and any workflow `concurrency` guard.
5. In scope as unavoidable mechanics: `permissions: contents: write` on both workflows; Go version sourced from `indexer/go.mod` via setup-go `go-version-file`.
6. Semver validation and commit/tag logic are DUPLICATED INLINE in both workflow files. No composite action, no `.github/scripts/`, no shared abstraction (KISS/YAGNI per GEN-001/GEN-002 for two call sites).
7. `.pre-commit-config.yaml`: add an `exclude` for `bin/` to the `check-added-large-files` hook only. Do not raise the global 1024kb limit.
8. `CLAUDE.md` (root, `/home/agent/workspace/CLAUDE.md`) is updated; `README.md` is out of scope.
9. Third-party actions are pinned to MAJOR VERSION TAGS (e.g. `actions/checkout@v5`) — not commit SHAs, not exact release tags. Verify the current major of each action at implementation time.

## Verification Strategy

GitHub Actions workflows cannot be executed in this environment (no runner, no GitHub API side effects). Verification is therefore static, in three layers:

1. **Schema/syntax**: both workflow files parse as YAML (`check-yaml` via `pre-commit run --all-files`) and pass an actionlint-style review (valid `workflow_dispatch` inputs, valid `needs` graph, valid `runs-on` values, no unpinned or wrongly-pinned action refs, no unquoted `${{ }}` injection into shell).
2. **Local reproduction of the underlying commands** (early verification point for Phase 1):
   - From `indexer/`: `CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -o <scratch>/indexer-linux-amd64 .` and the linux/arm64 and darwin/arm64 equivalents — all three must succeed and match the §6.1 filenames.
   - From the repo root: build a host-native indexer and run `./indexer --source . --output <scratch>/standards-tree.yaml`, verifying exit 0 (Phase 2).
   - Extract the inline validation and skip-if-unchanged shell snippets from the workflow files and run them locally against good/bad semvers, existing/absent tags, and changed/unchanged tree files.
3. **Contract review**: diff every literal in the workflows against the Reference Contracts section below (filenames, tag formats, bot identity, CLI flags, branch name).

## Failure Modes

- [ ] `actions/checkout` does not fetch tags by default — tag-existence validation silently passes without `fetch-depth: 0` or `fetch-tags: true` before `git tag -l`
- [ ] `actions/upload-artifact` drops POSIX file modes — without `chmod +x` before `git add`, `bin/indexer-*` lands as mode 100644 and breaks REQ-3.1 execution
- [ ] Unanchored or lax semver regex accepts `v0.2.0`, `0.2.0-rc1`, or `0.2` — must accept exactly `major.minor.patch` (§6.2)
- [ ] `${{ inputs.semver }}` interpolated directly into `run:` shell enables script injection — pass via `env:` and reference as a shell variable, especially in the validation step that runs before the format gate
- [ ] Committing a byte-identical `standards-tree.yaml` makes `git commit` exit non-zero — the skip-if-unchanged guard (standards workflow only) must prevent a false pipeline failure while the tag step still runs
- [ ] Tag created before the release commit is pushed (or pointing at the pre-commit SHA) — tag must point at the pushed release commit, or at HEAD when the standards commit was legitimately skipped
- [ ] Missing `permissions: contents: write` — push and tag fail with the default token
- [ ] New YAML files with CRLF endings or a missing trailing newline fail `check-yaml` / `end-of-file-fixer` / `mixed-line-ending`
- [ ] Release binaries exceed the 1024kb `check-added-large-files` limit — Task 3's `bin/` exclude on that hook only
- [ ] darwin/arm64 built on a Linux runner (or vice versa) — REQ-2.1 requires `macos-latest` for darwin/arm64; set `GOOS`/`GOARCH` explicitly on all builds anyway for determinism
- [ ] Accepted risks per explicit waiver (do not "fix"): no concurrency guard (concurrent dispatches may race on push to `main`), no missing-binary diagnostic in the standards workflow, no skip-if-unchanged for the indexer binaries

## Reference Contracts

- **Workflow files**: `.github/workflows/release-indexer.yaml`, `.github/workflows/release-standards.yaml` (both new; `.github/` does not yet exist)
- **Trigger**: `workflow_dispatch` with required input `semver`; format exactly `major.minor.patch` (e.g. `1.2.3`), no prefixes or suffixes (§6.2)
- **Binary filenames** (§6.1): `indexer-linux-amd64`, `indexer-linux-arm64`, `indexer-darwin-arm64`, all under `bin/`
- **Tag formats**: `v{semver}-indexer` (REQ-2.4), `v{semver}-standards` (REQ-3.3), on `main`
- **Bot identity** (§6.3, both workflows — supersedes REQ-3.2's `ci-bot`):
  - `git config --global user.name "github-actions[bot]"`
  - `git config --global user.email "github-actions[bot]@users.noreply.github.com"`
- **Indexer CLI** (REQ-3.1): `bin/indexer-linux-amd64 --source . --output standards-tree.yaml` from repo root; contract `--source <dir> --output <file> [--prefix <p>]`; exit 0 = validated and written, exit 1 = anything else; output deterministic, writes atomic, failed run leaves the previous tree untouched
- **Runners**: `ubuntu-latest` for both linux builds (cross-compile is safe: pure Go, `CGO_ENABLED=0`) and for the standards job; `macos-latest` (Apple Silicon) for darwin/arm64 only
- **Go toolchain**: from the `go` directive in `indexer/go.mod` via setup-go `go-version-file` — never hardcoded
- **Action pinning**: major version tags only (e.g. `actions/checkout@v5`); verify each action's current major at implementation time
- **Permissions**: `permissions: contents: write` on both workflows
- **Repo facts**: `bin/` is not gitignored (root `.gitignore` lists only `PLAN.md`/`REVIEW.md`; `bin/.gitignore` is an empty keep-file), so `git add bin/indexer-*` needs no `-f`; the indexer walk skips dot-prefixed directories, so `.github/workflows/*.yaml` cannot join the standards tree and no `indexer/integration_test.go` snapshot changes are required
