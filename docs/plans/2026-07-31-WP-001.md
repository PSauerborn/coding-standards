# Work Plan: Standards Indexer Implementation

Work Plan ID: WP-001
Created Date: 2026-07-31
Type: feature
Spec: docs/specs/SPEC-001.md
Scale: Large
Description: Standalone Go CLI in `indexer/` that walks the standards corpus, parses frontmatter and example files, validates the corpus, and emits a deterministic `standards-tree.yaml` index.
Estimated Impact: ~31 files (all new except `indexer/go.mod`)

## Objective

Agents must select applicable standards without reading the whole corpus (18
standards documents, 28 example files, ~3,200 lines). Build `indexer`, a
single-shot CLI (`indexer --source <dir> --output <file> [--prefix <p>]`) that
generates the `standards-tree.yaml` index from document frontmatter and example
metadata, validates the corpus with actionable diagnostics, and exits non-zero
on any validation failure without writing output.

## Background

The repository currently ships a hand-authored reference tree at
`docs/standards-tree.yaml`. There is no tooling to regenerate or validate it, so
corpus drift (uncited examples, stale statement IDs, broken parent links) goes
undetected. SPEC-001 defines the indexer; `indexer/` currently contains only a
`go.mod`. The standards corpus itself is READ-ONLY input (spec §3.2) — this plan
adds tooling only, never edits standards documents, example files, or the
reference tree.

## Implementation Phases

Layout constraint for all tasks: flat `package main` directly in `indexer/`
(GO-008 — single-binary project; no `cmd/` or `internal/`), snake_case
filenames (GO-006), one `_test.go` per source file (GO-027), unit fixture data
under `indexer/tests/data/` (GO-031).

Fixture-placement constraint for all tasks (RISK-001, CRITICAL):
`indexer/tests/data/` sits INSIDE the `--source` root that AC-1/AC-6/AC-10 and
the Phase 3 smoke run index, and `indexer/` is neither dot-prefixed nor an
`examples/` directory. Every synthetic fixture corpus MUST therefore live under
the dot-prefixed directory `indexer/tests/data/.corpora/<case>/`, so REQ-1's
existing dot-directory exclusion covers it with no spec change. No task may
place a fixture standards document or fixture `examples/` directory anywhere
the real-corpus walker can reach.

### Phase 1: Foundation and Parsing Core (Estimated tasks: 5)

**Purpose**: First vertical slice — module tooling, data models, and the two
parsers (frontmatter, example files) that everything else consumes. Proves the
corpus is machine-readable exactly as the spec's input contracts describe.
**Verification**: `make test` and `make lint` in `indexer/` pass; early
verification point — a discovery unit test over the real corpus finds exactly
18 documents and a frontmatter parse test round-trips a real document.

#### Tasks

Identification level only — coverage and dependencies, no per-task implementation
detail (that belongs to `task-decomposer`):

- Task 1: Module scaffolding and tooling. Update `indexer/go.mod`
  (module `github.com/PSauerborn/standards/indexer`, go >= 1.25 per GO-001)
  adding `go.yaml.in/yaml/v3` (runtime) and `stretchr/testify` (test-only);
  produce `go.sum`, `indexer/Makefile` with build/test/lint/fmt targets
  (GEN-004, MAKE-001), and `indexer/.golangci.yml` (GO-004). testify
  transitively requires the archived `gopkg.in/yaml.v3`, so it WILL appear in
  `go.sum` (RISK-012): record in `indexer/go.mod` comments that it is a
  test-only transitive requirement never imported by indexer code, add a
  `depguard` deny rule for `gopkg.in/yaml.v3` in `indexer/.golangci.yml`, and
  verify `go list -deps` for the binary excludes it. Explicit exit condition
  (RISK-022): `make lint` and `make test` green on the bare scaffold before any
  later task begins; if golangci-lint cannot parse the go1.26 toolchain, pin
  the `go` directive to the highest supported version still satisfying GO-001
  (>= 1.25). Depends on: none.
- Task 2: Data models and error types. `indexer/types.go` (Document,
  Frontmatter, Node, ExampleEntry, Tree, run Config per GO-010) including
  scope scalar→list normalization; `indexer/errors.go` (GO-016/GO-017 typed
  errors plus an aggregate error type supporting collect-all-then-fail — NOT
  fail-fast returns, per spec §7 partial-failure semantics). The aggregate
  design must support cascade suppression (RISK-006): documents that failed
  parsing/validation are marked so dependent checks can be suppressed, and
  aggregated diagnostics are sorted by path for reproducible output. With
  `types_test.go` and `errors_test.go`. Depends on: Task 1.
- Task 3: Frontmatter extraction and parsing. `indexer/frontmatter.go`:
  delimit and YAML-parse frontmatter — the opening `---` MUST be the file's
  first line (byte offset 0), with the closing delimiter found by line scan
  from there; never scan for a first `---` mid-file and never inspect fenced
  code blocks (RISK-002: `README.md` contains fenced YAML with `---`-delimited
  `title:`/`parent:` content that would otherwise become a phantom 19th node
  duplicating `golang/API.md`). Required-key validation for `title`,
  `description`, `scope`, `topics` (present-but-empty `topics` is a failure;
  only `title` governs discovery — a discovered document missing the other
  required keys is a validation error, not a skipped file); diagnostics name
  file and cause. With `frontmatter_test.go`. Depends on: Task 2.
- Task 4: Document discovery and statement-ID extraction.
  `indexer/discovery.go`: filesystem walk excluding `examples/` directories
  and dot-prefixed directories; title-key discovery rule; extraction of
  statement IDs from discovered document bodies. Discovery MUST parse
  frontmatter of candidate files — never grep for citation-shaped or ID-shaped
  lines. ID handling (RISK-004): one shared, exported ID regex (e.g.
  `` `\[([A-Z][A-Z0-9]*(?:-[A-Z0-9]+)*-\d+)\]` ``) used by BOTH the document
  statement extractor and the example `Statements:` parser — the corpus has
  eighteen prefix families, six of them three-segment (`GO-API`, `GO-DOCKER`,
  `GO-WRK`, `JS-DOCKER`, `PY-API`, `PY-DOCKER`), and a naive `[A-Z]+-[0-9]+`
  truncates them self-consistently so REQ-9 still passes while emitted
  `statements` are wrong; table-driven test enumerating all eighteen real
  prefix families. Statement extraction collects only statement DEFINITIONS
  (RISK-005): a backticked ID anchored at line start (allowing leading
  indentation and list markers) followed by a MUST/SHOULD marker, with fenced
  code blocks skipped — never any backticked `[ID]` token anywhere in the
  body. Unit tests include: a non-hidden fixture with frontmatter but no
  `title` so the title rule is asserted independently of the dot-directory
  filter; a README-shaped regression fixture (fenced YAML block with `---`
  delimiters, `title:`, `examples:`, a `Statements:` line and an ID heading)
  asserting zero nodes, zero citations, and zero statement IDs (RISK-002).
  With `discovery_test.go` and supporting fixtures under
  `indexer/tests/data/.corpora/` (dot-prefixed — RISK-001). Depends on: Task 3.
- Task 5: Example file parsing and citation resolution.
  `indexer/examples.go`: resolve each `examples:` entry against the citing
  document's directory; escape detection (RISK-010) by resolving, `Clean`ing,
  then requiring `filepath.Rel(sourceRoot, resolved)` not to begin with `..`,
  and rejecting absolute entries — never substring-matching `..`; fixtures:
  `../../etc/passwd` (must fail), `examples/../examples/config.md` (must
  PASS), `/abs/path.md` (must fail). Fail on a missing example file naming
  BOTH the citing standard and the missing path (AC-7); parse the
  `# [<ID>] <Title>` heading (ID stripped from emitted title) and the ordered
  `Statements:` IDs using the shared ID regex from Task 4 (RISK-004); fail on
  missing heading or `Statements:` line and on duplicate IDs. With
  `examples_test.go` and fixtures under `indexer/tests/data/.corpora/`.
  Depends on: Task 2, Task 4 (shared ID regex).

### Phase 2: Tree Assembly, Corpus Validation, Deterministic Rendering (Estimated tasks: 3)

**Purpose**: Turn parsed documents into the validated, deterministically
rendered tree — hierarchy, corpus-level cross-checks (REQ-8/REQ-9), and
`yaml.Node`-based output.
**Verification**: Unit tests demonstrate hierarchy facts (AC-2 shape), the
REQ-9 union rule on a synthetic dual-citation fixture, and repeated-render
byte equality including a map-heavy `aliases` fixture.

#### Tasks

- Task 6: Tree assembly. `indexer/tree.go`: parent-based hierarchy from
  `parent:` (path relative to source root); fail naming child and parent when
  `parent:` names no discovered document; cycle detection listing cycle
  members (A→B→A); sibling ordering by path; multi-root tolerance (not an
  error). Path emission (RISK-009): every emitted path — node AND example —
  funnels through a single `emitPath()` helper applying `filepath.ToSlash`,
  `path.Clean`, and the prefix join; table-driven test over prefix spellings
  (`p`, `p/`, `p//`, `./p`) asserting exactly one separator and that example
  paths are prefixed too. `--prefix` is applied strictly as the final emission
  step, never during parsing or lookup (RISK-016 — otherwise parent lookup
  breaks or the wrong example file resolves); test that `--prefix x` yields an
  identical tree SHAPE to no prefix. With `tree_test.go`. Depends on: Task 4,
  Task 5 (example paths flow through `emitPath()`).
- Task 7: Corpus-level validation. `indexer/validate.go`: REQ-8 — every
  `*.md` under any `examples/` directory must be cited by some discovered
  document's `examples:` frontmatter, else fail naming the uncited file. The
  REQ-8 uncited-example scan MUST reuse the same walker and exclusion set as
  discovery — a second, unfiltered walk reintroduces RISK-001 by treating
  fixture examples under `indexer/tests/data/.corpora/` as uncited real-corpus
  files. REQ-9 — the example's heading ID must appear on its `Statements:`
  line, and every `Statements:` ID must occur as a statement DEFINITION (per
  Task 4's definition-only extraction, RISK-005) in the UNION of the citing
  standards, else fail naming example, ID, and citing standard(s). Cascade
  suppression (RISK-006): documents marked as failed by earlier stages
  suppress dependent REQ-8/REQ-9 checks (their citations still count as
  "cited"; their children do not report unknown-parent). `validate_test.go`
  MUST include: a synthetic dual-citation fixture where an ID is satisfied by
  the second citing standard only (the union path is unexercised by the real
  corpus — all 28 examples are cited exactly once); a fixture where a standard
  mentions a foreign ID both in prose and inside a code fence, asserting REQ-9
  still fails for an example citing it (RISK-005). Depends on: Task 4, Task 5.
- Task 8: Deterministic rendering. `indexer/render.go`: marshal the tree via
  the `yaml.Node` API with EXPLICIT, code-declared key ordering for every
  mapping — never rely on incidental encoder map-key sorting, which a later
  refactor silently drops (RISK-007); assert the exact emitted `aliases` key
  sequence in `render_test.go`; run render/determinism tests under
  `-count=10 -shuffle=on`. Scalar handling (RISK-011): marshal exclusively
  through the YAML library with default scalar styles (every node's `scope`
  contains patterns like `'*'`, the YAML alias indicator); include an
  emit-then-reparse structural round trip asserting an emitted `'*'` scope
  re-parses to the string `*`. Field presence (RISK-015): `scope` always a
  list; `examples` in frontmatter order; assert a node with neither declared
  `aliases` nor `examples` omits BOTH keys while still carrying
  `children: []`, and that the root carries `aliases`. Render fixtures include
  an example-bearing node so the render↔example coupling is exercised where it
  is introduced (RISK-021). Output written only after full validation passes.
  Depends on: Task 5, Task 6 (RISK-021 — render consumes both ExampleEntry
  data and the assembled tree).

#### Phase Completion Criteria

- [ ] Hierarchy, cycle, unknown-parent, prefix, REQ-8, REQ-9 (including union and definition-only extraction), and determinism unit tests pass

- Task 11: AC-10 structural comparator. A dedicated comparator source file
  with its own `_test.go` (GO-027) — this is production-grade logic, not a
  test helper buried in the suite (RISK-020). The comparator MUST normalize
  sibling node order (the reference tree's sibling order genuinely differs
  from REQ-6's sort-by-path — e.g. `general/MAKEFILES.md` is followed by
  `databases/POSTGRES.md`, `databases/DYNAMODB.md`, `testing/ACCEPTANCE.md`)
  and normalize NOTHING else (RISK-003): `examples`, `statements`, `topics`,
  and `scope` are compared as ORDERED sequences, and an absent key is
  distinguished from an empty one. Negative self-tests mutate the parsed
  reference — swap two statements, reorder examples, drop a topic, add
  `examples: []` — and assert the comparator reports a difference for each.
  The AC-10 test compares the generated tree against `docs/standards-tree.yaml`

## Reference Contracts

- **CLI contract**: `indexer --source <dir> --output <file> [--prefix <p>]`;
  exit 0 on success, non-zero on any validation failure; diagnostics to stderr.
- **Output schema** (authoritative reference: `docs/standards-tree.yaml`; per
  user decision, `CLAUDE.md` — currently a heading-only stub — and the external
  coding-standards skill are NOT validation targets): top-level `nodes:` list
  of root nodes; node = `path`, `title`, `description`, `scope` (always a
  list), `topics` (list), optional `aliases` (map), optional `examples` (list
  of `{path, title, statements}`), `children` (list, always present).
- **Input contract — standards documents**: YAML frontmatter; required
  `title`, `description`, `scope` (list or scalar), `topics`; optional
  `parent` (path relative to source root), `examples` (paths relative to the
  document's directory), `aliases`. Frontmatter opens with `---` at the file's
  first line; content inside fenced code blocks is never frontmatter.
- **Input contract — example files**: first line `# [<ID>] <Title>`; a
  `Statements:` line listing every covered ID as `` `[<ID>]` ``; no
  frontmatter.
- **Statement-ID grammar**: one shared regex (e.g.
  `` `\[([A-Z][A-Z0-9]*(?:-[A-Z0-9]+)*-\d+)\]` ``) used by both the document
  statement extractor and the `Statements:` parser; the corpus has eighteen
  prefix families — `GO`, `PY`, `JS`, `API`, `DDB`, `PG`, `TF`, `LOG`, `GEN`,
  `MAKE`, `ACPT`, `DOCKER`, and three-segment `GO-API`, `GO-DOCKER`, `GO-WRK`,
  `JS-DOCKER`, `PY-API`, `PY-DOCKER`. A statement DEFINITION is a
  line-anchored backticked ID followed by a MUST/SHOULD marker, outside fenced
  code blocks.
- **Path semantics (REQ-5)**: all emitted paths relative to `--source`;
  `--prefix` prepended with trailing slash normalized so exactly one `/`
  separates prefix and path; prefix applied only at emission.
- **YAML library**: `go.yaml.in/yaml/v3` (maintained YAML-org fork, near
  drop-in for `gopkg.in/yaml.v3`). `gopkg.in/yaml.v3` is archived/unmaintained
  (April 2025) and MUST NOT be imported by indexer code — it appears in
  `go.sum` only as a test-only transitive requirement of testify, and a
  `depguard` rule denies direct import. The `yaml.Node` API with code-declared
  key ordering is the mechanism for deterministic output.
- **Concrete corpus values for assertions**: 18 nodes; 28 example entries;
  single root `GENERAL.md` with an 8-key `aliases` map
  (go/js/ts/py/postgres/pg/deploy/containerization); `python/DOCKER.md` child
  of `general/DOCKER.md`; `golang/API.md` child of `golang/GENERAL.md`;
  `javascript/GENERAL.md` scope `['*.js', '*.ts', '*.vue']`;
  `python/examples/GENERAL/config.md` → title `Configuration Loading`,
  statements `PY-019`–`PY-024`. Reference-tree sibling order differs from
  sort-by-path (`general/MAKEFILES.md` → `databases/POSTGRES.md` →
  `databases/DYNAMODB.md` → `testing/ACCEPTANCE.md`), so the AC-10 comparator
  must normalize sibling node order — and only that.
- **Module**: `github.com/PSauerborn/standards/indexer`, flat `package main`.
