## Observations (non-blocking, no remediation task)

Recorded so they are not lost, but neither weakens the mitigation it belongs to:

1. **RISK-007** — the risk plan asked for render/determinism tests to be *run*
   under `-count=10 -shuffle=on`. `make test` is plain `go test ./...`
   (`indexer/Makefile:8-11`), so the invocation is not encoded in a repeatable
   target; it exists as a 10-iteration in-process loop plus a `t.Log` hint
   (`indexer/render_test.go:268-281`). This is the form TASK-008.md:42 explicitly
   sanctioned during decomposition ("document the invocation in the
   Makefile-independent test comment or a `t.Log`"), and every substantive
   element of the countermeasure — explicit `yaml.Node` key ordering with no map
   iteration, the exact alias key-sequence assertion, and AC-6 as two separate
   process invocations — is implemented and verified. If a CI configuration is
   added later, a `test-determinism` target running
   `go test -run 'TestRenderTree|TestIntegrationDeterminism' -count=10 -shuffle=on`
   would close the gap.
2. **RISK-018** — the countermeasure's third clause (a note in the test file that
   `docs/` templates must stay frontmatter-free) is not present in
   `integration_test.go`; the equivalent warning is in `indexer/README.md:62-70`,
   which is where a template author is more likely to read it.
3. **Manifest completeness** — the manifest's "Risk mitigations implemented and
   verified" section omits RISK-018, RISK-019 and RISK-020 entirely. All three
   are in fact honored by the changeset (see their rows); the omission is a gap
   in the manifest's record, not in the implementation.
