# Risk Plan: Standards Indexer

Work Plan ID: WP-001
Created Date: 2026-07-31

## Risks and Countermeasures

This risk plan covers WP-001 (`docs/plans/2026-07-31-WP-001.md`, implementing
`docs/specs/SPEC-001.md`). Likelihood and Impact are rated `L`/`M`/`H`;
Severity is expressed as `Low`/`Medium`/`High`/`Critical` to match the review
schema.

Weighting note used throughout: this tool gates which standards every
downstream agent reads. A **false negative** (a broken or drifted corpus
accepted, or a plausible-but-wrong tree emitted) degrades every consumer
silently and is weighted as higher impact than a **false positive** (a valid
corpus rejected), which fails loudly and is self-announcing. Risks that produce
silently-wrong output are therefore rated above risks that produce crashes.

Risks flagged **[GAP]** are, in my judgement, not covered by the current work
plan's Failure Modes section and need explicit handling during decomposition.

### Technical Risks

Risks arising from the technical approach, dependencies, tooling, or the
architecture of the change.

| ID | Risk | Likelihood | Impact | Severity | Countermeasure |
| --- | --- | --- | --- | --- | --- |
| RISK-001 | **[GAP] Test fixture corpora poison the real-corpus run.** Task 10 places synthetic corpora under `indexer/tests/data/`, which is *inside* the `--source` root used by AC-1/AC-6/AC-10 and by the Phase 3 smoke run (`indexer --source . --output <tmp>`). `indexer/` is neither a dot-directory nor an `examples/` directory, so the walker descends into it: fixture standards documents carrying `title:` frontmatter become extra nodes (AC-1's "exactly 18" and AC-10 both fail), and fixture files under fixture `examples/` directories are by construction uncited, so REQ-8 fails the *real* repository with a non-zero exit. The tool becomes unusable on its own repo the moment Task 4's fixtures land. | H | H | Critical | Nest every fixture corpus under a dot-prefixed directory (e.g. `indexer/tests/data/.corpora/<case>/`) so REQ-1's existing dot-directory exclusion covers it with no spec change; **the REQ-8 uncited-example scan MUST reuse the same walker and exclusion set as discovery** (a second, unfiltered walk reintroduces the failure). Add a regression test that runs the full pipeline with `--source <repo root>` *while fixtures exist on disk* and asserts exit 0 and exactly 18 nodes (Tasks 4, 7, 10). |
| RISK-002 | **[GAP] `README.md`'s fenced YAML block is parsed as frontmatter.** `README.md` has no frontmatter, but lines 28–39 contain a ```` ```yaml ```` block whose body is delimited by `---` lines and contains `title: Golang REST API Standards`, `parent: golang/GENERAL.md`, `scope`, and `topics`; lines 60–72 additionally contain a `# [GO-022] Configuration Loading` heading, a `Statements:` line, and an `examples:` list. Any frontmatter extractor that scans for the *first* `---` line rather than requiring it at byte offset 0 produces a phantom 19th node named `README.md` that looks entirely plausible (a duplicate of `golang/API.md` parented under `golang/GENERAL.md`) and drags fake citations into REQ-8/REQ-9. The plan's Failure Modes note the grep hazard but not this delimiter-position hazard. | M | H | High | Require the opening `---` to be the file's first line (offset 0) and the closing `---` to be the next line consisting solely of `---`; never scan for delimiters mid-file and never inspect fenced blocks. Add a README-shaped regression fixture (fenced YAML with `---`, `examples:`, `Statements:`, and an ID heading) asserting it yields zero nodes, zero citations, and zero statement IDs (Tasks 3, 4). |
| RISK-003 | **AC-10's structural comparator is over-normalized and becomes vacuous.** AC-10 is the only end-to-end net catching a plausible-but-wrong tree, and the reference's sibling order genuinely differs from REQ-6's sort-by-path (e.g. `databases/POSTGRES.md` follows `general/MAKEFILES.md`), so *some* normalization is mandatory. A comparator that sorts everything — `examples`, `statements`, `topics`, `scope` — or that treats an absent field as equal to an empty one, will pass against a tree with reordered examples, reordered statements, or spurious empty keys. The strongest correctness check silently stops checking. | M | H | High | Normalize sibling node lists **only**; compare `examples`, `statements`, `topics`, and `scope` as ordered sequences, and distinguish an absent key from an empty one. Add a negative self-test for the comparator: take the parsed reference, produce mutated copies (swap two statement IDs, reorder two examples, drop one topic, add `examples: []`), and assert the comparator reports a difference for each (Task 10). |
| RISK-004 | **Statement-ID pattern mishandles multi-segment IDs.** The corpus uses ten ID families with differing shapes: `GEN-001`, `GO-001`, `PY-019`, `API-002`, `LOG-002`, `DDB-001`, `TF-014`, `ACPT-001`, plus three-segment forms `PY-DOCKER-001`, `GO-DOCKER-001`, `JS-DOCKER-002`, `GO-API-002`, `PY-API-005`, `GO-WRK-011`. A naive `[A-Z]+-[0-9]+` matches only the `DOCKER-001` tail. Because the same pattern is applied on both sides of the REQ-9 check, the truncation is self-consistent and validation still passes — but the emitted `statements` values are wrong, misrouting agents to the wrong example files. | M | H | High | One shared, exported ID regex used by both the document statement extractor and the example `Statements:` parser (e.g. `` `\[([A-Z][A-Z0-9]*(?:-[A-Z0-9]+)*-\d+)\]` ``); table-driven unit test enumerating all ten real prefix families and asserting full-token capture; AC-4 (`PY-019`–`PY-024`) and AC-10 (`PY-DOCKER-001`) retained as end-to-end nets (Tasks 4, 5, 10). |
| RISK-005 | **[GAP] REQ-9 accepts merely-mentioned IDs (false-negative validation).** REQ-9 requires each `Statements:` ID to *occur as a statement* in a citing standard. If extraction collects any backticked `` `[ID]` `` token anywhere in the body — including prose cross-references and fenced code blocks — an example citing an ID the standard only *mentions* is accepted. Corpus rot then passes validation, which is the silent failure this tool exists to prevent. | M | H | High | Extract only statement *definitions*: a backticked ID anchored at the start of a line (allowing list-marker/indent prefixes) and followed by a `**MUST**`/`**SHOULD**` marker; skip fenced code blocks. Add a fixture where a standard mentions a foreign ID in prose and inside a code fence, and assert REQ-9 still fails for an example citing it (Tasks 4, 7). |
| RISK-006 | **[GAP] Collect-all aggregation produces cascading, misdirecting diagnostics.** Spec §7 mandates collecting every error before exiting. One unparseable or key-missing document therefore also surfaces as: unknown-`parent` errors for each of its children, "uncited example" errors for every example it cites, and REQ-9 failures for those examples. A single root cause emits five-plus diagnostics, and the operator fixes the wrong thing — the exact opposite of the "actionable diagnostics" requirement. | M | M | Medium | Mark documents that failed parsing/validation and suppress dependent checks for them (their citations still count as "cited" for REQ-8; their children report against the failed parent, not as unknown-parent). Assert in `main_test.go`/integration that a corpus with one corrupted document yields exactly one diagnostic naming that file, and that the aggregate error's ordering is deterministic (sorted by path) so diagnostics are reproducible (Tasks 2, 7, 9). |
| RISK-007 | **Determinism achieved incidentally rather than explicitly, and under-tested.** The 8-key `aliases` map on the root is the known hazard, but two second-order problems compound it: (a) marshalling a Go map may appear deterministic because the YAML encoder happens to sort keys, leaving determinism dependent on undocumented library behaviour that a later refactor to `yaml.Node` silently drops; (b) an AC-6 test that renders twice inside one process may not exercise the same nondeterminism as two separate binary invocations. Failures surface intermittently, not consistently. | M | H | High | Build the output through `yaml.Node` with explicit, code-declared key ordering for every mapping (never rely on encoder behaviour); assert the exact emitted `aliases` key sequence in `render_test.go`; run render/determinism tests under `-count=10 -shuffle=on`; implement AC-6 as two *separate process* invocations of the built binary compared byte-for-byte (Tasks 8, 10). |
| RISK-008 | **[GAP] Non-deterministic or environment-bound content in the output.** A generated-on header, tool version, hostname, or an absolute path leaking into `path` values breaks AC-6 across machines/runs and makes the artifact non-reproducible. Related: `--source .` versus `--source /abs/path` must produce identical output since all paths are relative to the source root. | L | M | Medium | Prohibit timestamps, versions, and absolute paths in the emitted document; add a test asserting the output contains no absolute filesystem path and that runs with a relative `--source` and an absolute `--source` (from different working directories) are byte-identical (Tasks 8, 10). |
| RISK-009 | **Path normalization defects under prefixing and joining.** `filepath` operations yield OS separators and un-cleaned segments; `--prefix` may arrive as `p`, `p/`, `p//`, or `./p`. Emitted paths must be slash-form, cleaned, and separated from the prefix by exactly one `/` (REQ-5/AC-5), for *example* paths as well as node paths. | M | M | Medium | Funnel every emitted path through a single `emitPath()` helper applying `filepath.ToSlash` + `path.Clean` + prefix join; table-driven test over prefix spellings (`p`, `p/`, `p//`, `./p`, empty) asserting exactly one separator and asserting example paths are prefixed too (Task 6). |
| RISK-010 | **`../` escape detection implemented as substring matching.** Rejecting entries containing `..` textually gives a false positive for a legitimate `examples/../examples/config.md` and a false negative for an absolute path or a path that escapes only after cleaning. | L | M | Medium | Resolve the entry against the citing document's directory, `Clean` it, then require `filepath.Rel(sourceRoot, resolved)` to not begin with `..` and reject absolute entries outright; fixtures for `../../etc/passwd`, `examples/../examples/config.md` (must pass), and `/abs/path.md` (Task 5). |
| RISK-011 | **YAML re-emission corrupts special scalars.** Every node's `scope` includes patterns such as `'*'`; `*` is the YAML alias indicator and `[`/`>`/`#`-leading values need quoting. Hand-rolled string formatting, or a `yaml.Node` built with an explicit style/tag that suppresses quoting, yields output that is unparseable or, worse, parses to something different. | L | H | Medium | Marshal exclusively through the YAML library with default scalar styles; add an emit → re-parse → structural-equality round-trip assertion in `render_test.go`, including an explicit assertion that an emitted `'*'` scope re-parses to the string `*` (Task 8). |
| RISK-012 | **[GAP] `stretchr/testify` transitively depends on the excluded `gopkg.in/yaml.v3`.** testify requires `gopkg.in/yaml.v3` (for `YAMLEq`), so the archived, explicitly-excluded module will appear in `go.mod`/`go.sum`. Reviewers will read this as a violation of the settled dependency constraint, and nothing currently prevents a future test from importing it directly. | M | M | Medium | Record in `indexer/go.mod` and the plan Notes that `gopkg.in/yaml.v3` is a test-only transitive requirement of testify and is never imported by indexer code; add a `depguard` deny rule for `gopkg.in/yaml.v3` in `indexer/.golangci.yml`; verify `go list -deps .` for the binary does not include it (Task 1). |
| RISK-013 | **Temp-copy harness fidelity and machine-binding.** AC-7/AC-8/AC-9 mutate a `t.TempDir()` copy of the real corpus. A copy helper that skips dot-directories, empty directories, or symlinks yields a corpus that differs from the one under test, weakening the failure-path assertions; locating the repo root via a hardcoded absolute path (`/Users/pascal/...`) makes the suite machine-bound and CI-hostile. | M | M | Medium | Locate the repository root via `runtime.Caller` plus a relative join, never a literal absolute path; use one shared `copyCorpus` helper; before mutating, assert the copy produces a clean baseline run with 18 nodes and 28 example entries so a defective copy fails as itself rather than as a false AC-7/8/9 pass (Task 10). |
| RISK-014 | **Live-corpus coupling with no supported refresh path.** AC-1's hardcoded 18 and AC-10's hand-authored reference bind the suite to today's repository content, while "no regeneration target" is an explicit non-delivery — so the first legitimate standards document added breaks two acceptance tests with no sanctioned way to update `docs/standards-tree.yaml`. The plan records this hazard but supplies no remedy. | M | M | Medium | Derive the expected node count from the corpus (count of frontmatter-`title` documents) for structural assertions, and keep `18` as one clearly-labelled snapshot assertion whose failure message states "corpus changed — update this constant and refresh docs/standards-tree.yaml"; make the AC-10 failure message print the exact refresh procedure (`indexer --source . --output /tmp/tree.yaml`, then hand-merge preserving comments); document both in `indexer/README` or test comments (Task 10). |
| RISK-015 | **Absent-versus-empty field drift.** REQ-3 requires `children` always present and `aliases`/`examples` omitted when undeclared. Manual `yaml.Node` construction makes `examples: []`/`aliases: {}` easy to emit accidentally, and consumers traversing the tree may branch on key presence. | M | M | Medium | Explicit `render_test.go` assertions on a node with neither aliases nor examples (keys absent, `children: []` present) and on the root (aliases present); comparator must distinguish absent from empty (see RISK-003) so AC-10 catches drift (Task 8). |
| RISK-016 | **`--prefix` applied before hierarchy and citation resolution.** `parent:` values and `examples:` entries are unprefixed (relative to source root / document directory). Applying the prefix during parsing rather than at emission breaks parent lookup (spurious unknown-parent failures) or, worse, silently changes which example file is resolved. | M | M | Medium | Apply the prefix strictly as the final emission step; add a test asserting `--prefix x` yields an identical tree shape to no prefix (AC-2 hierarchy facts hold under prefix) and that every node *and* example path is prefixed (Tasks 6, 10). |
| RISK-017 | **Output write side effects on failure.** A truncated or stale output file left behind by a failing run, or a run whose `--output` parent directory does not exist, contradicts spec §7 ("output written only when validation passes in full") and can hand consumers a half-written index. | L | M | Medium | Write to a temporary file in the output directory and `rename` atomically only after the aggregate error is empty; test that a failing corpus leaves no new output file and does not truncate a pre-existing one, and that a missing output directory produces a clear diagnostic (Task 9). |
| RISK-018 | **Repository markdown outside the corpus later gains `title:` frontmatter.** `PLAN.md`, `README.md`, `CLAUDE.md`, `docs/specs/*`, and `docs/plans/**` are all walked. They are frontmatter-free today (the work-plan and task templates use heading + plain key lines, not YAML frontmatter), but any future document template that adds YAML frontmatter with `title:` silently becomes a standards node. | L | M | Low | Document the discovery rule prominently in the indexer README; keep the exactly-18 assertion as the tripwire (RISK-014 makes its failure message actionable); note in the test file that document templates under `docs/` must remain frontmatter-free (Task 10). |
| RISK-019 | **Consumer-contract compatibility is asserted only indirectly.** Spec §6 requires the output to stay consumable by the traversal algorithm in `CLAUDE.md`, but `CLAUDE.md` is a heading-only stub, so no test can verify the consumer contract; AC-10 against the hand-authored reference is the only proxy. | L | M | Low | Treat `docs/standards-tree.yaml` as the authoritative schema contract and state so in the indexer README; keep the emit → re-parse round trip (RISK-011) so the artifact is at minimum machine-readable; no further action while `CLAUDE.md` remains a stub (Tasks 8, 10). |

## Risks Judged Inadequately Covered by the Current Plan

Called out explicitly per the analysis brief. These are the items where the
plan's Failure Modes section is silent or insufficient:

1. **RISK-001 (Critical)** — the plan places fixture corpora inside the
   directory tree it indexes and never addresses the interaction. This breaks
   the Phase 3 completion criterion (`indexer --source . --output <tmp>` exits
   0) as soon as Task 4's fixtures exist, and is the single highest-value item
   to resolve before decomposition.
2. **RISK-002 (High)** — the plan anticipates grep-based citation collection
   but not the closely related failure where a lenient frontmatter delimiter
   scan turns `README.md`'s fenced YAML sample into a phantom node. The
   resulting tree is plausible, not obviously broken.
3. **RISK-005 (High)** — REQ-9's statement-occurrence check is a
   false-negative surface. The plan specifies extracting `` `[<ID>]` ``
   tokens without constraining *where* they may occur, so cross-references and
   code samples can satisfy the check.
4. **RISK-003 (High)** — the plan correctly forbids a golden byte diff for
   AC-10 but does not specify what the structural comparator must *preserve*.
   Under-specified normalization is how AC-10 quietly stops being a check.
5. **RISK-006 (Medium)** — the collect-all requirement is recorded, but the
   cascading-diagnostic consequence (one root cause, many misleading errors)
   is not, and it directly undermines the "actionable diagnostics" objective.
6. **RISK-012 (Medium)** — testify's transitive dependency on the explicitly
   excluded `gopkg.in/yaml.v3` will appear in `go.sum` and will be read as a
   constraint violation unless pre-empted.
